## 1. 불변 (건드리지 않는 것)

- 플레이어 자기 공격 0개. **새 플레이어 동사 0개** — 가드 브레이크·홀드 패리·점프 금지.
- 금 = 패리, 적 = 대시. **세 번째 색·세 번째 대응 색을 만들지 않는다.**
- **예고(플래시) → 타격 시간은 공격별로 항상 일정.** 새 동작마다 이 약속을 어떻게 지키는지 §3 에 적었다.
- 훔친 기술은 기존 4종(`C.RIPOSTE_KINDS`)으로만 실행된다. `RIPOSTE_KINDS` 는 바꾸지 않는다.
- 아레나 경계 `V.MIN_X`(60)·`V.MAX_X`(900) 불변. 플레이어가 물리적으로 갇히는 일은 없어야 한다(`C.ARENA.SAFE_MIN_W` 200 하한).
- 챕터 1(VESPER·SERAPH·GRAVEN·MIRROR)은 **한 줄도 동작이 바뀌지 않는다.** 새 엔진 경로는 새 `kind` 가 올 때만 탄다.
- `window.__RIPOSTE.getState()` 는 **필드 추가만**. 보스 정의 테이블은 전투 중 변형 금지(`tests/state.mjs`).
- 대사(`js/story.js`)는 바꾸지 않는다 — §2 의 배정이 기존 대사와 대체로 맞는다(§2 각 보스의 "대사" 줄). 예외 하나: HOLLOW 의 "칼끝이 빛나는 그 순간"은 **보스 무기 끝**의 빛이라, 플레이어 몸에 붙는 표식과는 결이 다르다 — 어둠 테마는 맞으므로 이번엔 두고 §7 에 올린다.

## 2. 재활용 판정 기준과 보스 배정

### 2.1 무엇을 "재활용"으로 보는가

공격 하나의 **동작 서명** = `kind/tell` + 행동을 바꾸는 표지(`linger`·`echo`).
`volley`(같은 것을 반복)·`anchor`(자리만 다름)·수치(windup·reach·speed·damage)는 서명에 넣지 않는다 — 플레이어가 하는 일이 바뀌지 않기 때문이다.

- 챕터 1 이 쓰는 서명: `melee/gold` · `melee/red` · `projectile/gold` · `projectile/red` · `zone/red` · `charge/red`.
- **규칙: 챕터 2 이후 보스는 "먼저 등록된 보스 누구와든 서명이 같은 공격"을 최대 1개까지만 가진다.** 이 1개는 손패 공급용 기본기다. 나머지는 전부 그 보스가 처음 쓰는 서명이어야 한다.
- 새 동작은 새 `kind` 라서 첫 소유 보스 뒤로는 자동으로 "재활용"이 된다 → **한 동작 = 한 보스가 판정기로 강제된다.**
- 이 검사는 `overlapIntended` 로 면제되지 않는다.
- **이름만 바꾼 우회를 막는다**: `kind` 는 엔진이 아는 것(기존 4종 + `js/motions.js` 에 등록된 동작)만 허용한다 — 수치 변주에 새 kind 이름을 붙여 "새 서명"으로 통과시키는 길을 닫는다. 새 동작을 넣으려면 엔진 표에 등록해야 하고, 그건 리뷰 대상인 엔진 변경이다.
- 반격 자세의 벌 반격은 서명 `stance/counter` 로 센다(`stanceCounter: true`). 이 표지는 **같은 보스의 `stance.counter` 가 가리키고 패턴이 직접 부르지 않는 공격**에만 인정한다 — 자기 선언으로 재활용 카운트를 피하는 통로가 되지 않게.
- 알려진 한계: 서명은 방향·위치를 보지 않는다(미래의 "수직 빔"과 "수평 빔"은 같은 `sweep/red`). 지금 8보스에는 해당 사례가 없다.

현재 상태(이 규칙으로 잰 값, 재설계 전): LANTERN 3 · CHORUS 4 · BASTION 3 · AVARICE 9 · SENTINEL 2 · TEMPEST 4 · HOLLOW 4 · ADAMANT 4 — **8보스 전원 FAIL**. 판정기를 먼저 고쳐 이 FAIL 을 재현한 뒤 보스를 고친다(계획 Task 1).

### 2.3 동작별 "플레이어가 새로 하는 일"

| 동작 | 보스 | 챕터 1 과 다른 읽기 / 행동 |
|---|---|---|
| 부메랑 | LANTERN | 같은 탄의 **색이 비행 중에 바뀐다**(적→금). 앞으로 오는 적색은 대시로 넘기고, **등 뒤에서** 돌아오는 금색을 뒤돌아 받는다 |
| 악보 | CHORUS | 예고에서 **불규칙한 리듬을 먼저 들려주고**, 그 리듬대로 친다. 두 번째 타격부터는 플래시가 없다 — **외워서** 받는다 |
| 메아리 | CHORUS | 친 공격을 **보스가 있던 자리**의 잔상이 같은 박자로 다시 친다. 보스는 그새 반대편으로 건너가 있다 — **위치를 기억**한다 |
| 기둥 | BASTION | 등 뒤에 **넘을 수 없는 기둥**이 선다. 물러서기·뒤로 대시가 막힌다 — 아머 보스 앞에서 **정면으로 받아내게** 만든다 |
| 끌어당김 | AVARICE | 예고 동안 **보스 쪽으로 끌려간다.** 버티며 걸어 나가 헛치게 만들지, 끌려가며 타이밍을 다시 잡을지 고른다 |
| 쓸기 빔 | SENTINEL | 등 뒤 벽에서 붉은 띠가 레인을 쓸고 온다. 도망쳐도 따라잡힌다 — **빔 쪽으로** 대시해 넘어야 한다(방향 선택) |
| 협공 | TEMPEST | 앞(금)과 뒤(적)에서 **일정한 시차**로 온다. 앞을 받고 곧바로 뒤를 넘는다 — **두 방향 · 두 색 · 순서** |
| 표식 | HOLLOW | 플레이어 몸에 붙어 **따라다니는 카운트다운.** 보스를 보지 않고 **자기 몸의 빛**을 읽는다. 그 사이 다른 공격이 겹친다 |
| 반격 자세 | ADAMANT | 이 윈드업 중에 치면 **벌을 받는다.** 지금까지 "윈드업 중 명중 = 카운터"였던 규칙을 뒤집는 **참기** 읽기 |

**반격 자세가 세 번째 텔을 만들지 않는 이유**: 들어오는 공격의 대응은 여전히 금(끝의 강타 = 패리)·적(벌 반격 = 대시)뿐이다. "지금 치면 안 된다"는 것은 ADAMANT 방벽·GRAVEN 아머와 같은 **보스 상태 표시**다(방패를 든 자세 + 회색 윤곽 + 팝 `GUARD`). 색을 새로 쓰지 않는다.

### 2.4 보스별 구성 (출발값 — 판정기와 봇 실측이 확정한다)

수치는 출발점이다. 챕터 3 계획의 관행대로 **판정기가 걸리면 수치가 아니라 구성을 바꾸고**, hp·par·gap 은 밸런스 태스크가 정한다(hp 는 길이 레버가 아니다 — handover 교훈 3).
아래 패턴 목록은 출발안이다. 구현 계획(Task 8~15)이 **"모든 패턴에 금 공격 ≥1"**(손패 공급 — HOLLOW 교훈) 규칙으로 다듬은 목록이 정본이다(예: 금이 없는 `[line]`·`[claim]`·`[plunder]`·`[scissor]` 단독 패턴을 금 공격과 묶었다).

**LANTERN (5)** — 대사: "이 손엔 금, 저 손엔 빨강 … 거짓말." = 색이 바뀌는 부메랑.
- flicker (기존 그대로) · **orb** = 부메랑(out 적 / back 금), 훔치면 ORB(shot 14) · P2 **orb2** = 부메랑 2발(volley 2).
- P1 `[behind, flicker]`, `[orb]`, `[orb, wait, flicker]`, `[flicker, wait, orb]` · P2 `[orb2]`, `[behind, flicker, orb]`, `[orb, behind, flicker]`, `[behind, flicker, behind, flicker]`.
- 🔴 부메랑 비행 중 순간이동은 P2 에서만(돌아오는 방향이 보스 쪽과 어긋나 읽기가 두 배로 어려워진다 — 사람 플레이테스트 항목).

**CHORUS (6)** — 대사: "하나가 묻고, 하나가 답한다." = 악보(묻고 답하기) · 메아리(돌림노래).
- **refrain** = 악보(3타, 간격 0.45·0.90), 훔치면 TWIN(slash 13) · **canon** = 근접 금 + 메아리(잔상이 0.7초 뒤 같은 자리에서 다시 친다), 훔치면 CANON(lunge 15) · P2 **refrain2** = 악보 4타(0.35·0.35·0.70) · scissor(기존, P2).
- P1 `[refrain]`, `[canon]`, `[canon, cross, canon]`(잔상 둘이 양쪽에) , `[cross, refrain]` · P2 `[refrain2]`, `[canon, cross, refrain2]`, `[cross, canon, scissor]`, `[scissor]`.

**BASTION (7)** — 대사: "뭘 보내든 돌려보낸다 … 이 문 넘은 놈은 없다." = 되받아치기 · 문(기둥).
- salvo (기존) · **gate** = 기둥 1개(플레이어 등 뒤 150px, 4.0초), 붉은 텔 · P2 **cage** = 기둥 2개(등 뒤 + 보스와 플레이어 사이 — 투사체만 오가는 방).
- P1 `[salvo]`, `[gate, salvo]`, `[far, salvo, wait, salvo]`, `[gate, wait, salvo]` · P2 `[cage, salvo, wait, salvo]`(랠리), `[gate, salvo, salvo]`, `[far, gate, salvo]`, `[salvo, far, salvo]`.
- 금 공급원은 salvo 하나다 — **모든 패턴에 salvo 가 있다**(HOLLOW 교훈: 붉은 것만 있는 패턴은 손패를 말린다).
- 🔴 cage 는 플레이어 칸이 `SAFE_MIN_W` 이상일 때만 선다(§3.6).

**AVARICE (8)** — 대사: "저도 걷는 사람이라서요." = 끌어당김.
- count (기존, fallback) · **haul** = 끌어당김 + 금 타격, 훔치면 HAUL(slash 20) · **plunder** = 끌어당김 + 적 잡기(피해 1 + 손패 전부 강탈, 기존 plunder 규칙).
- 되돌림: `MIRROR_MAP = { COUNT: 'count', HAUL: 'haul' }`. 빼앗긴 HAUL 을 되돌려 쓰면 **다시 끌려간다.**
- P1 `[loot]`, `[haul]`, `[close, loot]`, `[plunder]` · P2 `[all]`, `[haul, loot]`, `[plunder, loot]`, `[loot, wait, loot, wait, loot]`.

**SENTINEL (9)** — 대사: "그 자리에 서시오 … 설 자리만 지우겠소." = 지속 구역 · 경계선(빔).
- lance (기존) · claim (기존, linger) · **line** = 쓸기 빔(폭 90, 속도 320).
- P1 `[lance]`, `[line]`, `[claim]`, `[line, wait, lance]` · P2 `[claim, wait, lance]`, `[line, wait, lance]`, `[lance, wait, lance]`, `[lance]`.
- 🔴 **claim 과 line 은 한 패턴에 넣지 않는다** — 빔을 넘는 대시의 착지점이 지속 구역일 수 있다(갇힘). 섞고 싶으면 봇 실측으로 착지점이 안전함을 먼저 보인다.

**TEMPEST (10)** — 대사: "전부는 못 받는다고 … 버릴 걸 먼저 고르라고." = 협공.
- surge (기존) · **squall** = 협공(앞 금 1발 → 0.45초 뒤 뒤 적 1발), 훔치면 SQUALL(shot 14) · P2 **squall2** = 앞은 surge 3연발, 뒤는 적 1발 — 전부는 못 받는다.
- far/near 태그 유지(`onPickPattern`). near 는 `[back, …]` 로 물러난 뒤에만 쏜다(코앞 생성 탄 금지 — 기존 교훈).

**HOLLOW (11)** — 대사: "남은 건 하나더라. 칼끝이 빛나는 그 순간." = 표식(내 몸의 빛).
- ember (기존, back 뒤에만) · **brand** = 금 표식(부착 1.4초 뒤 폭발), 훔치면 BRAND(lunge 20) · P2 **brand-red** = 적 표식(폭발 순간 대시).
- P1 `[brand]`, `[back, ember]`, `[brand, back, ember]`(표식이 도는 동안 탄이 온다), `[back, ember, brand]` · P2 `[brand-red, brand]`, `[brand, back, ember]`, `[back, ember, brand-red]`, `[brand, brand-red]`.
- 표식·카운트다운 링은 **어둠 위에** 그린다(§2.2 어둠 규칙).

**ADAMANT (12)** — 대사: "막을 뿐." = 방벽 · 반격 자세.
- shards (기존, 방벽 재료) · **guard** = 반격 자세(자세 0.9초 → 끝에 금 강타 reach 190, 훔치면 CLEAVE(slam 24). 자세 중 맞으면 즉시 적 반격 **retort**(reach 240, windup = `MIN_WINDUP`)).
- P1(wall) `[far, shards]`, `[far, shards, close, guard]` · (any) `[guard]`, `[close, guard]` · P2(wall) `[far, shards, shards]`, `[far, shards, close, guard]` · (any) `[guard, wait, guard]`, `[close, guard]`.
- P2 counterOnly 와 짝: shards 윈드업에는 shot 으로 카운터를 넣고, guard 윈드업에는 참는다.

## 3. 엔진 — 새 동작 9개

### 3.1 구조

- **새 파일 `js/motions.js`** — `window.MOTIONS[kind] = { melee?, begin?, tick?, active?, activeEnd?, state? }` 표. `index.html` 에서 `js/boss.js` 바로 뒤에 로드한다(보스 정의 파일들은 로드 시점에 이 표를 읽지 않는다).
- `js/boss.js` 는 **새 kind 가 오면 이 표로 넘기기만** 한다. 기존 kind(`melee`·`projectile`·`zone`·`charge`)의 코드 경로는 그대로다. 근접류 새 동작(`pull`·`stance`·`score`)은 표의 `melee: true` 로 기존 접근·lunge·`testMelee`·궤적 그리기를 재사용한다.
- 공격 인스턴스에 `a.spawns = []` 를 더한다. 아직 "살아나지 않은"(`pending`) 스폰은 경직·페이즈 전환 때 `cancelAttackSpawns` 가 같이 지운다 — 기존 존과 같은 규칙("보스를 끊었는데 결과가 그대로 온다" = 텔과 결과가 어긋남).
- **원격 타격 공용 판정** `Game.resolveRemoteHit(src)` — 표식 폭발·메아리 잔상처럼 **보스 몸이 아닌 곳에서 오는 타격.** 퍼펙트 = 훔침(보스 경직 없음 — 멀리서 보스를 끊는 보상은 주지 않는다), 블록 = 기존 블록, 무적 = 통과, 그 외 = 피해. 기존 `resolveBossHit` 는 건드리지 않는다.
- 새 월드 엔티티(`js/entities.js`): `Beam`(쓸기 빔) · `Pillar`(기둥) · `Mark`(표식) · `Echo`(메아리 잔상). 게임은 배열 4개(`beams`·`pillars`·`marks`·`echoes`)를 갖고 `clearWorld` 가 비운다.
- `getState()` 추가 필드: `beams:[{x,w,vx,pending}]` · `pillars:[{x,w,tRise,up}]` · `marks:[{x,tRemain,tell}]` · `echoes:[{x,reach,tell,hitAt}]`. `currentAttack` 에 `remote: true`(이 공격 자체는 windup 끝에 몸으로 때리지 않는다 — 봇이 헛패리하지 않게)와 `stance: true`(반격 자세 windup 중).
- 전역 수치는 `C.MOTION` 블록, 보스별 수치는 보스 파일(기존 원칙).

### 3.2 부메랑 `kind:'boomerang'` (LANTERN)

- 정의: `proj:{speed,r,y,damage,reflectDamage,shape}` + `boomerang:{ turnDist, backTime, backTell }`. 정의의 `tell` = 나갈 때 색(적).
- 나간다: windup 끝에 투사체 발사(기존 투사체와 같다). 적색이므로 대시로 넘는다(`pierced`).
- 돈다: 탄이 플레이어를 **`turnDist` 지나간 지점** 또는 아레나 끝에서 돈다. 도는 순간 **그 자리에서 두 번째 텔 버스트**(`backTell` 색 + 소리)가 터지고, 속도는 `|탄 - 플레이어| / backTime` 로 정한다 → **두 번째 텔 → 타격 = `backTime` 으로 항상 일정**(플레이어가 서 있을 때). 속도 상한은 `C.MOTION.BOOMERANG_SPEED_MAX`.
- 플레이어가 벽에 붙어 **받는 거리(`PARRY.PROJECTILE_CATCH`) 안에서 돌게 되면 탄은 부서진다** — 예고와 타격이 같은 순간이 되는 귀환을 만들지 않는다.
- 돌아온다: `tell = backTell`(금), `pierced = false`. 퍼펙트 패리하면 **보스 쪽으로** 반사된다 — 기존 `reflect()` 는 속도를 뒤집기만 해서 등 뒤에서 온 탄을 벽으로 보낸다. `reflect(toward)` 인자를 더하고 **부메랑 귀환탄만** 넘긴다(기존 탄의 반사는 한 줄도 안 바뀐다).
- 받지 못한 귀환탄은 **플레이어를 지나간 뒤** 보스에 닿으면 사라진다(보스가 받는다). 지나가기 전에는 보스 몸을 통과한다 — 보스가 순간이동해 귀환 경로 위에 서 있어도 탄을 먹지 않는다.
- 훔침: `steal`(shot).

### 3.3 협공 `kind:'pincer'` (TEMPEST)

- 정의: `proj`(앞 탄) + `pincer:{ backDist, backSpeed, backTell, gap, backR }`. 정의의 `tell` = 앞 탄 색(금).
- windup 끝: 앞 탄 발사(기존 투사체). 동시에 앞 탄의 도착 예상 `ETA = (거리 - PARRY_CATCH) / speed` 를 재고, 뒤 탄 생성을 `max(0, ETA + gap - backDist/backSpeed)` 뒤로 예약한다.
- 뒤 탄: 생성 순간 플레이어 **등 뒤 `backDist`**(아레나 안으로 자름)에 나타나며 **그 자리에서 적 텔 버스트**. 뒤 탄 텔 → 타격 = `backDist / backSpeed` 로 일정. 앞 → 뒤 시차 = `gap` 으로 일정(플레이어가 서 있을 때).
- 생성 순간 등 뒤 공간이 `PINCER_MIN_ROOM` 보다 좁으면(그새 벽으로 물러섰다) **뒤 탄은 생기지 않는다** — 몸 위에 예고 없이 생기는 탄을 만들지 않는다. 시작할 때의 같은 검사(`canBegin`)와 짝이다.
- volley 가 있으면 앞 탄은 기존 volley 대로 여러 발(`squall2`), 뒤 탄은 마지막 앞 탄 기준으로 예약한다.
- 훔침: 앞 탄 `steal`.

### 3.4 쓸기 빔 `kind:'sweep'` (SENTINEL)

- 정의: `beam:{ w, speed, damage }`. 정의의 `tell` = 적.
- windup 시작: 플레이어 **등 뒤 벽**(보스 반대쪽 끝)에 빔이 `pending` 상태로 나타난다(윤곽 + 적 텔 버스트). windup 끝에 보스 쪽으로 움직이기 시작한다.
- 판정: 빔이 플레이어와 겹치는 순간 무적(대시)이 아니면 피해 1회(`hitDone`). 반대편 벽을 넘으면 사라진다.
- 설계 수치 근거: 대시 속도 190/0.22 = 864px/s. 빔 속도 320 이면 상대 속도 1184px/s, 빔(90) + 몸(28)을 지나는 데 0.10초 < 대시 무적 0.20초 → **빔 쪽으로** 대시하면 넘는다. 빔 반대쪽으로 대시하면 대시 후 걷는 속도 265 < 320 이라 따라잡힌다 → 방향 선택이 강제된다.
- 텔 → 타격: 거리에 따라 다르다(돌진 charge 와 같은 성질 — 스펙 §2.2 에서 이미 허용된 형태). 대신 빔은 windup 내내 보인다.

### 3.5 끌어당김 `kind:'pull'` (AVARICE)

- 정의: 근접 정의(`reach`·`damage`·`swing`·`steal`·`plunder`) + `pull:{ speed }`. `melee: true`, **접근하지 않는다**(보스가 오지 않고 플레이어를 부른다).
- windup 동안 매 스텝 플레이어를 보스 쪽으로 `pull.speed` 만큼 옮긴다. **대시 중에는 끌지 않는다.** `pull.speed` < `PLAYER.SPEED`(265) 여야 걸어서 버틸 수 있다(출발 170 → 버티면 초당 95px 씩 멀어진다).
- windup 끝: 기존 근접 타격(`testMelee`). 사거리 밖이면 헛친다 — 버틴 보상.
- 금(haul) = 패리/훔침. 적(plunder) = 대시, 맞으면 기존 plunder 규칙(손패 전부 강탈).
- 텔 → 타격 = windup 으로 일정(근접과 같다).

### 3.6 기둥 `kind:'pillar'` (BASTION)

- 정의: `pillar:{ w, up, dist, count }`(count 1 = 등 뒤, 2 = 등 뒤 + 앞). 정의의 `tell` = 적.
- windup 시작: 기둥 자리를 정하고 바닥 경고(존과 같은 스트립, `pending`)를 깐다. 등 뒤 기둥 = `플레이어 - 보스방향 × dist`, 앞 기둥 = 플레이어와 보스의 중간.
- 🔴 **안전 규칙**: 기둥이 선 뒤 플레이어가 있는 칸의 폭이 `C.ARENA.SAFE_MIN_W`(200) 미만이 되거나 기둥이 아레나 밖이면 **그 스텝을 건너뛴다**(돌진의 `MIN_CHARGE_RUN` 과 같은 방식).
- windup 끝: 기둥이 선다. 그 순간 기둥 폭 안에 있으면 피해(적 — 대시로 피한다). 이후 `up` 초 동안 **플레이어의 걷기·대시·밀림(블록 밀림 포함)이 기둥을 통과하지 못한다** — 기둥은 설 때 플레이어가 있던 쪽을 기억하고 그 쪽으로만 되돌린다(순간 이동이 기둥 가운데를 넘어도 반대편으로 새지 않게). 보스와 투사체는 통과한다(되받아치기 랠리는 기둥을 사이에 두고 계속된다).
- 🔴 **서는 순간 칸 폭을 한 번 더 잰다** — windup 동안 플레이어가 기둥 자리 너머로 걸어가 칸이 `SAFE_MIN_W` 보다 좁아지면 서지 않는다.
- 대시가 기둥에 막혀도 무적 시간은 그대로 흐른다(대시 판정은 바뀌지 않는다).

### 3.7 표식 `kind:'mark'` (HOLLOW)

- 정의: `mark:{ delay, tell, damage }`. 정의의 `tell` = 보스 예고 색(표식 색과 같다).
- windup 시작: 보스 무기 끝 텔(기존). windup 끝: 플레이어에게 표식이 붙는다 — **그 순간 플레이어 위치에 두 번째 텔 버스트.** 표식은 플레이어를 따라다니며 줄어드는 링으로 남은 시간을 보여준다.
- `delay` 뒤 표식 위치(= 그때의 플레이어 위치)에서 폭발 → `resolveRemoteHit`. 금 = 패리(훔침), 적 = 대시.
- **두 번째 텔 → 폭발 = `delay` 로 항상 일정.** 보스는 그사이 다음 스텝을 진행한다(겹침이 이 동작의 핵심).
- 붙은 뒤에는 보스가 경직돼도 사라지지 않는다(이미 약속된 타격). 붙기 전(windup)에 끊기면 붙지 않는다.

### 3.8 반격 자세 `kind:'stance'` (ADAMANT)

- 정의: 근접 정의(끝의 강타) + `stance:{ counter: '<공격 id>' }`. `melee: true`(접근한다).
- windup = 자세. 보스 상태 표시 **3채널** — 색(회색)·모양(점선 링, `C.MOTION.STANCE_*`)·소리(`RAudio.guard()`, 낮은 울림). 이 게임에서 오판의 벌이 가장 큰 표시라 §2.2 의 3채널 원칙을 그대로 따른다. 예고 텔은 금(끝의 강타를 약속) — 금 tick 과 자세 울림이 함께 난다.
- 자세 중에 플레이어 리포스트(근접이든 손패 shot 이든)가 보스에 맞으면: **피해 0 · 손패 환급 없음**, 팝 `GUARD`, 진행 중 공격을 버리고 즉시 `stance.counter`(적 근접, windup = `MIN_WINDUP`, 접근 없음)를 시작한다. 반사탄(패리로 되돌린 보스 탄)은 자세를 건드리지 않는다 — 벌은 "참지 못한 것"에만 준다.
- 끝까지 참으면 windup 끝에 금 강타 → 패리하면 CLEAVE 를 훔친다.
- 카운터 판정과의 관계: 자세 windup 은 **카운터 창이 아니다.** 방벽이 서 있으면 방벽 판정이 먼저다(방벽에 튕긴 리포스트는 벌을 받지 않는다).

### 3.9 악보 `kind:'score'` (CHORUS)

- 정의: 근접 정의 + `score:{ notes:[간격…], gap }`. `melee: true`.
- **예고(콜)**: windup 시작 플래시와 함께 첫 음표, 이어서 `notes` 간격대로 음표 점멸(보스 머리 위 작은 점 + 짧은 음 `RAudio.note()`). 음표는 텔 버스트가 아니다(모양·소리가 다르다 — 예고의 예고).
- 콜이 끝나고 `gap`(× windup 배수, `MIN_WINDUP` 하한) 뒤 첫 타격. 이어지는 타격은 **플래시 없이** `notes` 간격 그대로. 모든 간격 ≥ `BOSS.MIN_VOLLEY_GAP`(0.35).
- windup 총길이 = 콜 길이 + gap. 첫 플래시 → 각 타격 시간이 모두 일정하다(콜과 응답이 같은 악보).
- 배수(P2 ×0.8·하드·어시스트)는 **gap 에만** 걸린다 — 콜과 응답의 리듬은 바뀌지 않는다.
- 매 타격 퍼펙트 = 훔침. 🔴 **남은 타격이 있으면 퍼펙트 패리가 보스를 경직시키지 않는다**(경직은 공격을 지워 악보를 끊는다) — 경직은 마지막 타격 뒤에만.
- **§2.2 와의 관계**: 두 번째 타격부터 텔이 없는 것은 이 게임에서 악보가 유일하다 — "개별 타격을 예고"가 아니라 "첫 예고에서 모든 타격 시각을 약속"하는 방식이다. 첫 플래시 → 각 타격 시간은 일정하므로 §2.2 의 일정성은 지키지만, 반응이 아니라 **기억**을 시험하는 새 범주다. 대화 1절에서 사용자가 "박마다 예고가 다시 뜨지 않는다"를 포함한 동작 목록을 승인했다(2026-09-23). 사람 플레이테스트가 "외울 수 없다"로 판정하면 §6 대로 응답에 작은 플래시를 되살린다.

### 3.10 메아리 `echo` (CHORUS)

- `kind` 가 아니라 근접 공격 정의의 표지 `echo:{ delay }`. 서명은 `melee/gold/echo`.
- 원 공격의 타격 순간 보스 위치를 기록하고, `delay` 뒤 그 자리에 **잔상**(`Echo`)이 나타나 **원 공격과 같은 windup·reach 로** 다시 친다. 잔상도 자기 플래시를 찍는다 → 잔상 텔 → 타격 = 원 windup(배수 포함)으로 일정.
- 판정은 `resolveRemoteHit`(퍼펙트 = 같은 카드 훔침). 원 공격이 windup 중 끊기면 메아리도 없다(타격이 일어난 공격만 메아리친다).
- `cross` 와 합치면 잔상과 본체가 **양쪽에서** 친다.

## 4. 봇·테스트

- `tests/motions.mjs`(신규, 브라우저·단위) — 동작마다 "플레이어가 해야 하는 일"을 한 줄씩 검증한다. 예: 부메랑은 대시로 넘긴 뒤 등 뒤에서 금으로 돌아온다 · 빔은 반대쪽 대시로는 맞고 빔 쪽 대시로는 넘는다 · 끌어당김을 걸어서 버티면 헛친다 · 기둥은 걷기와 대시를 막고 칸이 좁으면 서지 않는다 · 표식은 부착 뒤 `delay` 에 터지고 보스 경직으로 사라지지 않는다 · 자세 중 리포스트는 피해 0 + 반격, 참으면 끝에 금 강타 · 악보 두 번째 타격부터 플래시가 없다 · 메아리는 기록된 자리에서 친다 · 기존 `kind` 의 동작은 불변.
- `tests/bot.mjs` — 위협 원천을 더한다: 빔(**빔 쪽 방향키 + 대시**) · 기둥 상승 · 표식 · 메아리 잔상. `currentAttack.remote` 면 그 공격 자체의 hitAt 에는 반응하지 않는다. **새 배열이 비어 있으면 기존 동작과 한 줄도 다르지 않다**(챕터 1 결과 불변).
  - 봇은 악보를 외우지 않는다 — `currentAttack.hitAt` 이 다음 타격 시각을 알려 준다. 반격 자세는 봇이 원래 윈드업 중에 리포스트하지 않으므로 벌을 받지 않는다. ⇒ **"외우기·참기"의 난도는 봇이 못 잰다 — 사람 플레이테스트 항목**(HOLLOW 어둠과 같다).
- `tests/mash.mjs --expect-lose` — 연타 봇은 반격 자세에 벌을 받으므로 ADAMANT 에서 더 빨리 져야 한다(회귀 신호).
- `tests/state.mjs` — 새 엔티티·`a.spawns`·`a` 의 악보 진행 상태가 **보스 정의를 오염시키지 않는지**.
- `tools/boss-overlap.mjs --check` — §2.1 재활용 검사 추가. 표에 보스별 "재활용 공격 수(목록)"와 "새 서명 수" 열.

## 6. 되돌릴 기준

| 신호 | 되돌릴 것 |
|---|---|
| 사람이 부메랑 귀환을 "안 보이는 데서 맞았다"로 느낀다 | 귀환 텔 버스트 크기·`backTime` 상향 → 그래도면 귀환 색을 적으로(대시만) |
| 악보를 외울 수 없다(3타째에서 반복 사망) | 음표 수 3 으로 고정, 간격 차이 확대 → 그래도면 응답에도 작은 플래시 |
| 기둥 때문에 "갈 곳이 없다" | `up` 하향 · cage 폐기 |
| 끌어당김을 버틸 수 없다 | `pull.speed` 하향(항상 `PLAYER.SPEED` 의 2/3 이하) |
| 협공이 "패리하고 대시하는 순서 문제"로만 읽힌다(새 동작 중 차별화가 가장 약하다 — 설계 검토 지적) | `gap` 을 줄여 앞·뒤가 겹치는 구간을 만든다(받을지 넘을지 **고르게**) → 그래도면 뒤 탄을 금으로 바꿔 "어느 쪽을 받을지" 선택으로 |
| 표식과 다른 공격의 겹침이 "읽을 수 없다" | 표식 중에는 금 공격만 겹치게(패턴 제약) |
| 반격 자세가 "억울하다"(자세와 일반 윈드업을 못 가른다) | 자세 표시 강화 → 그래도면 반격을 금으로(패리 가능) |
| 새 동작 보스가 챕터 1 보다 재미없다 | **축 자체를 바꾼다. 수치로 덮지 않는다** |
